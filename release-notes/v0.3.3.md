# NetEaseNEXT 0.3.3（MSIX 0.3.3.3）

本次发布相较于上一版正式 Release **v0.3.2.6**，主要修复 WinUI 3 歌曲列表的选中指示条动效，以及播放控制栏中播放列表切歌造成的整表刷新问题。原先 v0.3.3.0 的发行附件已由本次 0.3.3.3 修订包替代；**v0.3.3 是同一个正式 Release，不需要分别安装两个修订版**。

## 歌曲选中指示条：恢复鼠标与触控动画

- 修复在歌单、歌曲列表中使用鼠标或触控点选其他歌曲时，左侧选中指示条直接跳到新位置、不播放伸缩过渡的问题。
- 根因是 WinUI `ListView` 在部分输入路径中先触发 `LayoutUpdated`、后触发 `SelectionChanged`：非动画布局刷新提前占用了新选中位置，让后续动画失去了起点。
- 现在保留旧位置作为动画起点，将本次选中变化延迟到输入事件结束后处理；同时处理点击过程中 `SelectedItem` 短暂清空的情况，避免误重置指示条。
- 保留上一版的 Fluent 伸缩指示条、上一首/下一首按钮反馈和侧栏选择动画。只调整歌曲列表选中状态的事件协调，不改变按钮动画参数。

## 远距离切歌：适配虚拟化列表

- 修复通过上一首/下一首、播放队列等方式跳到列表可视范围之外的歌曲时，蓝色指示条停留在旧歌曲旁边的问题。
- 当当前歌曲对应的 `ListViewItem` 尚未生成或已被虚拟化回收时，隐藏指示条并清除无效定位锚点。
- 滚动回当前歌曲所在区域、行容器重新出现后，指示条会显示在正确歌曲旁，不再从屏幕外执行不合理的跨区拉伸动画。
- 相邻且均可见的歌曲之间，仍保持原来的伸缩过渡。

## 播放控制栏的播放列表：切歌不再整表重绘

- 修复打开播放控制栏的播放列表后，在**列表内部点击另一首歌曲**，播放队列被重新创建、`ItemsSource` 重新绑定，导致整个列表重新绘制、滚动位置丢失，需要手动重新定位的问题。
- 原因是 `PlaybackService.PlayAsync()` 即使切换到已在队列内的歌曲，也会重新构造 `Queue` 数组。现在普通队列内切歌只更新当前曲目和选中状态，**保留原队列对象及已建立的列表项**。
- 播放器发出播放/暂停、媒体状态等通知时，不再反复设置相同的播放列表选中项，减少不必要的 UI 更新。
- 真正改变队列的操作（例如加入下一首、删除歌曲、明确以新歌单替换播放队列，以及随机播放重排）仍会正常更新数据源，不影响队列功能。

## 歌词页：自动跟随不再唤醒滚动条

- 修复歌词播放过程中每次自动居中当前歌词都会触发系统滚动条浮现的问题，减少歌词页右侧的无意义视觉干扰。
- 自动跟随使用原有的平滑 `ChangeView` 滚动，不改变歌词居中、动画和双语显示逻辑；歌词滚动条默认为 `Hidden`，而不是会禁用手动滚动的 `Disabled`。
- 鼠标进入或移动到歌词区域、滚轮、触控/鼠标按下及方向键翻阅歌词时，短暂恢复原生 `Auto` 滚动条，并在停止输入约 2 秒后重新隐藏；不为自动跟随另造自定义滚动条。
- 手动浏览歌词仍按原逻辑暂时中止自动跟随，闲置约 5 秒后恢复；歌词行点击跳转播放不受影响。

## 安装与兼容

- 本次正式发行包为 `NetEaseNEXT-0.3.3.3-x64.msix`；另附 Windows x64 便携版和公钥证书 `NetEaseNEXT.cer`。
- 支持 Windows 10 2004 及以上的 x64 系统。已安装并信任相同开发签名证书的用户，可直接升级至 MSIX 0.3.3.3；首次侧载请先信任随附的证书。
- 保持应用包身份不变，升级通常会保留现有账号、设置和播放记录。便携版请完整解压后运行。
- 此次不更改音频解码、网络请求、播放音质和账号登录等业务逻辑。

## 验证

- Windows x64 的 Release 构建和 Publish 成功。
- 已在实际设备上验证鼠标/触控点击动画、远距离切歌时指示条隐藏与恢复，以及在播放控制栏的播放列表中点击不同歌曲不会再触发整表重绘。
- 本次修订的重点是播放列表交互回归；不声称完成所有 Windows 版本、音质或联网场景的全面回归测试。
