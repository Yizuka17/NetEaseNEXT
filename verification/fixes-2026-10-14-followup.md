# 后续反馈修复

2026-10-14，Windows 11 x64。便携包位于 `artifacts/win-x64-followup`，已有运行实例没有被替换或关闭。

| 反馈 | 修改 |
| --- | --- |
| 播放中切换高音质失败 | 新音频先静音准备、解码并定位，再接替旧音频。远端流定位失败时使用临时文件；切换失败保留旧播放与进度。临时文件在换曲或退出后释放。 |
| 误报账号不支持音质 | 不再把接口返回的较低音质当成权限错误。显示实际返回音质，保留用户选择供下一首使用。 |
| 弹窗图标乱码 | 提示图标显式使用 Windows 符号字体；自选文字字体不覆盖模板里的符号字形。撤回对播放、导航等图标的矢量替换，保留 Windows 图标样式。 |
| 键盘控制 | 空格播放/暂停；Ctrl+左右切歌；Ctrl+上下调整音量；播放页左右跳转 5 秒。输入文字和弹窗中不截获播放快捷键。 |
| 滑动误触长按 | 用窗口坐标判断移动，移动超过 8 DIP 或列表开始滚动即取消长按；阻止触摸滑动后的原生延迟菜单。 |
| 歌单信息与按钮排版 | 标题去重，按钮按实际内容宽度换行，数量单列展示；歌单顶部信息随曲目一起滚动，避免高缩放、小窗口挤掉歌曲。 |
| SMTC 未知应用 | 注册 NetEaseNEXT 的应用标识与显示名称，绑定窗口 SMTC，发布播放状态、进度与歌曲元数据。 |
| 已赞图标 | 未赞保留 Windows 轮廓图标，已赞显示主题色实心图标。 |
| 我的播客与导航误选中 | 使用订阅列表接口 `dj_sublist`；导航只保留一个选中项，触摸悬停不再显示第二个选中背景。 |
| 定位歌曲位置 | 歌单和播放列表内提供浮动按钮，定位当前页的正在播放歌曲；播放栏移除该入口。 |
| 大播放页与全屏动画 | 保持同一播放页和控件，使用原生窗口边界切换，移除此次切换的封面连接与控件过渡。 |
| 消息、私信及未读 | 消息合并通知、回复与提及，私信单独展示；账号菜单分别显示未读数，条目左侧显示圆点，打开后标记已读。 |
| 单击歌曲响应慢 | 移除固定 300ms 等待，播放地址使用独立请求通道；双击同一首歌更新完整队列，避免重复打开音频。 |
| 其他页面的加载更多 | 歌曲、歌单、搜索、播客及专辑列表的分页入口移入对应列表末尾，居中、主题色、无边框，与评论和动态一致。 |

高音质真实网络检查中，无损和超清母带均解码、定位并续播成功；请求 Hi-Res 的样本由接口返回无损，正常续播并显示无损。测试使用现有会话，不改变账号权限，也没有执行发送、点赞、评论、删除或编辑歌单等远端写入。

最终便携包通过 97 项运行检查和 5 项 API 契约测试。运行检查验证了列表末尾分页入口的实际位置、歌单滚动头部、头像居中、提示图标字体、SMTC 应用标识、消息与私信分离，以及隐藏时停止界面更新并保留音频。

20 秒后台播放样本：主进程累计 CPU 218.75ms，工作集 298.8 MiB，私有内存 162.5 MiB；两个 API 工作进程均已空闲退出。原始记录见 `integration-followup-2026-10-14.json`、`background-followup-2026-10-14.json`、`quality-2026-10-14.json`。

真实触摸滑动、不同键盘焦点、多屏缩放及其他账号/歌曲的高音质仍需要对应设备和权限验收。后台进程样本不是整机功耗测量，不能据此声称达到 2W。
