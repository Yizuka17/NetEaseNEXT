# 本地歌单与下载流程评审

方向：在现有 WinUI 3 中让本地音乐沿用在线歌单的封面卡片和详情结构；下载按队列与失败记录分开。保留导航、主题、原生控件、歌手 - 专辑文案和页面短时淡入。

用户结果：创建有封面、绑定文件夹的歌单；目录内容自动更新；下载前确定目标最高音质；批量管理任务；失败项可直接处理；清空队列后仍能播放已下载的同一歌曲。

| 路径 | 之前 | 本次 |
| --- | --- | --- |
| 打开已有本地歌单 | 展开下拉并选择，2 次点击 | 点击封面卡片，1 次点击 |
| 绑定目录并持续同步 | 无此能力，只有一次性导入 | 编辑歌单集中选择封面、名称和目录；监听变化，手动刷新作为补充 |
| 暂停 N 项下载 | 逐首暂停，N 次 | 全部暂停，1 次 |
| 处理失败项 | 与普通任务混排 | 切到失败列表，歌曲行直接重试或移除 |
| 确定下载音质 | 菜单中选质量，没有最高目标的明确说明 | 确认对话框预填上次选择，说明降档规则和当前来源 |

计数仅统计主应用内的明确点击；文件选择器内的文件浏览和名称输入不计入上表。新建封面/绑定目录之前无法完成，因此没有虚构其前后减少的操作数。

主 Agent 先检查了真实 WinUI RenderTargetBitmap。早期失败页只显示计数、没有失败行，已将正常队列和失败记录拆成独立 ListView，复用同一行模板，并取消列表插入动画。验证现在检查原生行内实际显示的歌曲、错误和重试按钮，也逐张看图。

独立评审共两轮，不打分：

1. 查看七张当前图，对照 DESIGN.md。确认失败行、处理入口、本地歌单首页、目录编辑、详情和下载确认均符合范围；只指出对话框底部按钮约 32 DIP，低于触控要求。
2. 共享原生按钮样式改为至少 44 DIP 后，复核歌单编辑与下载确认图片，确认问题解决，无新增裁切或重叠。实际 XAML 断言也确认主按钮与取消按钮均为 44 DIP。

未另建主题或控件模板。保留原有导航淡入、原生对话框与按压反馈；下载列表使用直接迁移状态，避免切换瞬间空白。没有需要删除的多余介绍文字。图片由原生 XAML 生成，没有网页 lint 或录屏，静态图不能证明实体触屏、多显示器和鼠标输入行为。

证据：同目录的 `library-home-light.png`、`library-home-dark.png`、`library-folder-detail.png`、`library-playlist-editor.png`、`download-quality-prompt.png`、`download-queue.png`、`download-failures.png`。使用隔离临时目录、合成静音音频、应用图标封面和虚构曲名，不是用户曲库或实际下载记录。
