# 第三批反馈修复

2026-10-14，Windows 11 x64。新版便携包位于 `artifacts/win-x64-latest`。

| 反馈 | 修改 |
| --- | --- |
| 播放栏图标没对齐 | 保留原 Windows 字形，统一 20×20 图标容器、垂直居中及按钮高度；图标不受文字缩放影响。 |
| 歌单按钮没对齐 | 播放全部、收藏、评论、编辑和删除按钮统一为 44 DIP 高，图标与文字居中，继续按内容宽度换行。 |
| 消息提示太透明 | 两个提示栏均使用不透明的主题背景与边框，符号字体仍独立固定。 |
| 已读私信仍显示未读 | 持久保存本地已读抵扣与服务端计数快照，避免相同服务端计数恢复已读标记。服务端确认已读后清理抵扣，新消息按新增数量计数；兼容前一版已读记录。 |
| 已赞和未赞样式不一致 | 共用同一拇指轮廓；未赞为空心，已赞填充主题色，两种状态的尺寸和笔画一致。 |
| 大播放页拖动及窗口控制 | 顶部提供拖动区域，右上角恢复 Windows 原生最小化、最大化/还原、关闭按钮。全屏隐藏窗口按钮与返回按钮，清除拖动区域。 |
| 音质切换慢 | 选择时只保存音质偏好，立即提示“下一首歌曲生效”，保持当前音频与进度；换曲时请求新音质。菜单勾选偏好，播放栏显示实际播放音质。 |
| 滑动误触菜单 | 删除自定义长按计时器、手动弹菜单和触摸菜单拦截；让 WinUI 系统触摸手势处理长按、取消及滚动。 |
| 双击难以替换队列 | 接收列表已处理的原生双击事件，补充两次快速点击识别；触摸间隔允许 650ms。同一首歌的两次激活复用正在加载的音频，第二次更新完整队列。 |

运行检查覆盖：未读计数重复刷新、服务端确认后到达的新消息、并发双次歌曲激活、音质选择不重载当前音频及下一首采用新音质、图标中心位置、不透明提示背景、窗口控制、全屏无拖动区域、真实歌曲评论及消息读取。真实账号只执行读取，没有发送、点赞、删除或编辑远端内容。

最终便携包通过 104 项运行检查、5 项 API 契约测试；Release 构建与发布无警告、无错误。原始结果见 `integration-latest-2026-10-14.json`。

换曲音质检查通过：选择无损、Hi-Res、超清母带均保持当前音频；下一首均正常解码。该样本中 Hi-Res 接口返回无损，播放栏显示实际音质。原始结果见 `quality-next-song-2026-10-14.json`。

原生截图检查确认大播放页的右上角窗口按钮可见，原 Windows 播放图标保留。真实触屏长按、滑动与双击的手感仍需实机验收；自动化双次激活检查验证播放和队列行为，不代表触屏硬件输入验收。

首轮和第二批结果保留为历史记录，本文件描述当前行为，音质即时切换已被下一首生效替代。
