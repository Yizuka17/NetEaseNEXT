# 启动加载与后台网络资源

从 `8ca2bfc` 快进同步至远端 `5243871`，同步前工作区无未提交改动。本次修复保留在工作区，未提交或推送。

## 原因与修复

- API 桥接首次调用导入上游入口，上游会遍历并加载全部接口，随后加载 HTTP 服务模块。改为仅加载允许列表中的当前接口，并沿用依赖提供的请求实现。无网络的本地二维码协议检查修改前超过 15 秒而超时，修改后约 78–86 毫秒；这是本机测试样本，不代表所有设备的冷启动时间。
- 播放地址原先在每次 Node 重启后等待密钥注册；固定版本的注册请求没有超时。现在优先复用已有密钥，没有密钥时直接使用该接口支持的 EAPI 传输。账号、版权与音质权限仍由原接口判断。
- 启动预取吞掉错误后，页面会重新发起同一请求，再等待一轮超时。现在首次失败直接交给页面展示，用户明确重试时才继续请求。普通歌单详情与歌曲列表并行请求。
- 隐藏会取消所有页面加载，但恢复时只补载空白的推荐、歌单列表和部分目录页。现在记录中断及分页状态，恢复时补载原请求，保留已有行与分页位置；已完成的页面继续复用。
- 播放地址预热取消后，旧批次仍可能留在待处理表中，立即切歌会加入已经取消的任务。取消时立即移除无人使用的批次，当前播放请求的登记与查找也放在同一把锁下。
- 请求写入期间取消，旧请求可能在释放写入锁后才停止进程，误停刚被新请求复用的通道。现在在释放写入锁前清理可能写入不完整的通道。此问题由新增的立即取消预热再播放检查复现。
- 歌词取消时重置未完成的歌曲标记；恢复时也重新检查登录状态和音质。封面磁盘读取移出界面线程，正文传输增加完整的 20 秒超时，避免只收到响应头后一直占用下载名额。
